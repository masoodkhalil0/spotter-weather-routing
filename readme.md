# Weather-Aware Truck Routing

A React + Django web app that helps a truck driver choose the safest route
based on weather, load weight and travel time.

> Status: backend logic in progress. Hosted URL and Loom walkthrough will be
> added here when ready.

## How it works

1. The user enters origin, destination, departure time and load weight.
2. The backend fetches up to 3 route options from a routing API.
3. Each route is sampled at checkpoints (every 10 / 25 / 50 miles).
4. The truck's estimated arrival time at each checkpoint is used to pick the
   matching hourly weather forecast.
5. Each checkpoint is classified Low / Moderate / High / Severe / No Travel
   using the wind, rain and snow thresholds and the load rules.
6. Routes are ranked and the best one is recommended.

## Design decisions and assumptions

These are places where the requirements were ambiguous or the free APIs have
limits. Each is a deliberate choice.

- **Band boundaries.** The risk table has overlapping endpoints (for example
  0.25 appears in both Moderate and High). Each band is lower-bound inclusive
  and upper-bound exclusive: wind 35.0 mph is High, 34.9 is Moderate. For
  rain and snow the table says "> 1.00" and "> 3.0" for No Travel, so exactly
  1.00 in/hr rain and exactly 3.0 in/hr snow are Severe. Wind No Travel is
  >= 55 mph.
- **Load rules** use strict "greater than" comparisons (exactly 30,000 lb does
  not trigger the 45-54 mph rule) and never lower a risk level that is already
  higher.
- **Checkpoint risk** is the worst of wind, rain and snow at that point.
- **Rain** is rain plus showers as reported by Open-Meteo, so convective
  showers are not ignored.
- **Miles per risk level.** Each checkpoint represents half the distance to the
  previous checkpoint and half to the next, so the segment lengths add up to the
  exact route length. Severe and High miles are computed from these.
- **Recommendation order.** Routes are ranked by: any No Travel segment (a
  route containing one is never preferred over one without), No Travel miles,
  Severe miles, High miles, distance-weighted average risk, then travel time.
  No Travel is checked first because a route that cannot be driven should not
  win on fewer Severe miles.
- **Average risk** is weighted by distance, so a 50-mile stretch counts more
  than a 10-mile one.
- **ETA** assumes constant average speed along the route.
- **Truck speed.** OSRM assumes car speeds, so durations are divided by a 0.9
  truck factor.
- **Third route.** The free OSRM server often returns only 2 alternatives for
  long trips. When that happens, a third route is generated by routing through
  a via-point offset from the middle of the main route. It is accepted only if
  it is genuinely different and not much longer. The app handles 1 to 3 routes.
- **Caching** uses Django's in-memory cache. This avoids paid infrastructure and
  protects the free API quotas, and it resets when the server restarts.

## Known limitations

- Free-tier services have no uptime guarantee.
- The free Render backend sleeps after inactivity, so the first request can take
  about a minute.
- OSRM uses a car profile, not a true truck profile (no height or weight
  restrictions).
- Open-Meteo's free tier is for non-commercial use.

## Run the backend locally (Windows PowerShell)

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
copy .env.example .env      # then set SECRET_KEY in .env
python manage.py test
python manage.py runserver
```

Generate a secret key with:

```powershell
python -c "from django.core.management.utils import get_random_secret_key as g; print(g())"
```
